# Codyssey Compass 서비스 기획서

## 1. 목적과 대상 사용자

Codyssey Compass는 첫 웹 서비스를 기획하는 학습자가 막연한 아이디어를 실행 가능한 MVP 청사진으로 바꾸도록 돕는다. 주요 사용자는 AI 코딩 도구로 프로젝트를 만들고 싶지만 화면 구성과 개발 우선순위를 정하기 어려운 입문 개발자다.

## 2. 페이지·섹션 구조

| 구역 | 목적 | 핵심 행동 |
| --- | --- | --- |
| Home | 서비스 가치와 방향 소개 | AI 설계실로 이동 |
| 서비스 소개 | 해결하는 문제와 차별점 설명 | 기능 이해 |
| AI 설계실 | 아이디어·사용자·조건 입력 | 청사진 생성 |
| 결과 | 화면, AI 기능, 개발 순서, 위험 표시 | 결과 복사 |
| 진행 방법 | 아이디어부터 배포까지의 흐름 안내 | 실행 시작 |

한 페이지 안에서 메뉴로 각 섹션을 이동하며 데스크톱과 모바일을 모두 지원한다.

## 3. 기술의 역할

- HTML은 제목·내비게이션·폼·결과 영역의 의미 구조와 접근성 레이블을 담당한다.
- CSS는 디자인 토큰, 그리드, 컴포넌트 표현과 820px·520px 미디어쿼리의 반응형 배치를 담당한다.
- JavaScript는 폼 입력 검증, 로딩·성공·실패 상태, API 호출, 결과 DOM 생성을 담당한다.
- Python은 브라우저에서 전달된 데이터를 다시 검증하고 OpenAI를 호출한 후 출력 스키마와 HTTP 오류를 관리한다.

이 분리는 API 키를 브라우저에서 격리하고, 화면 변경과 AI 로직 변경을 독립적으로 배포하기 위한 기술적 경계다.

## 4. 핵심 AI 기능

- 입력: 서비스 아이디어(필수, 최대 600자), 대상 사용자, 우선 조건
- 출력: 이름, 설명, 3개 이상 화면, AI 입출력, 4단계 로드맵, 위험 요소
- 사용자 가치: 무엇을 어떤 순서로 만들지 빠르게 결정하고 첫 구현에 집중
- 실패 처리: 빈 입력은 즉시 차단한다. API 오류는 입력을 보존하고 한국어 메시지를 표시한다. 브라우저 요청은 20초 후 중단하고 재시도를 안내한다.

프롬프트는 코드의 `SYSTEM_PROMPT`를 v1 기준으로 관리한다. 새 버전에서는 응답 길이·예시 수·위험 항목을 한 번에 하나씩 바꾸고 동일한 고정 입력 세트로 JSON 성공률, 응답 시간, 토큰 비용을 비교한다. 짧은 출력 또는 더 작은 모델은 비용과 속도를 낮추지만 기획의 구체성이 감소할 수 있다.

## 5. 상태 변화

```text
idle → validating → loading → success
                 ├→ client-error → idle(입력 보존)
                 ├→ server-error → idle(재시도 가능)
                 └→ timeout → idle(재시도 가능)
```

폼 버튼과 상태 문구는 이 상태를 공유한다. `loading` 동안 중복 제출을 막고, 나머지 상태에서는 입력값을 유지한다.

## 6. 환경과 보안

- 로컬: `.env` 또는 `vercel dev`로 개발 키를 사용한다.
- Preview: 테스트 전용 키·낮은 사용 한도·Preview 허용 출처를 사용한다.
- Production: 운영 키·사용량 알림·`https://anyoungju.github.io` 허용 출처를 사용한다.
- 모든 환경에서 변수 이름은 `OPENAI_API_KEY`, `OPENAI_MODEL`, `ALLOWED_ORIGIN`으로 통일한다.
- 비밀키는 서버 환경변수에서만 읽으며 코드, 브라우저, 문서, 스크린샷에 기록하지 않는다.

유출 시에는 키 폐기 → 재발급 → 환경변수 교체 → 재배포 → Git·사용 로그 조사 → 협업자 공지 순서로 대응한다.

## 7. 확장 설계

- 프론트 기능 증가: `js/app.js`를 `api-client.js`, `form-state.js`, `result-view.js`로 분리하고 URL 라우팅을 도입한다.
- 사용자 기능: 인증 공급자와 데이터 저장소를 붙여 청사진 이력을 사용자별로 분리한다.
- 트래픽 증가: 사용자별 rate limit, Redis 결과 캐시, 비동기 작업 큐와 상태 조회 API를 추가한다.
- 운영 강화: Request ID 기반 로그, 지연·오류율 알림, 모델별 비용 대시보드를 추가한다.

## 8. 완료 기준

1. 두 가지 이상 화면 너비에서 메뉴, 폼, 결과가 깨지지 않는다.
2. 정상·빈 입력·과도한 입력·API 오류·시간 초과 흐름이 재현된다.
3. API 키를 설정한 Vercel 환경에서 실제 청사진이 생성된다.
4. 저장소와 배포 URL, 운영·보안 절차가 README에 연결된다.
